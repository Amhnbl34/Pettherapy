# 🐾 بک‌اند فروشگاه پت‌تراپی

بک‌اند کامل برای سایت پت‌تراپی؛ **بدون هیچ وابستگی** (نیازی به `npm install` نیست). فقط **Node.js نسخه ۱۸ یا بالاتر** لازم است.

## اجرا (۳ مرحله)

```bash
cd petherapy-backend
cp .env.example .env        # و شماره‌ی خودتان را در ADMIN_MOBILE بگذارید
npm start                   # یا:  node server.js
```

بعد در مرورگر باز کنید: **http://localhost:3000** (سایت) و **http://localhost:3000/admin** (پنل مدیریت)

### ورود مستقیم به پنل مدیر (/admin)
در `.env` این‌ها را بگذار و سرور را اجرا کن؛ حساب مدیر خودکار ساخته می‌شود و با **ایمیل یا شناسه + رمز** مستقیم از صفحه‌ی `/admin` وارد می‌شوی:
`ADMIN_USERNAME=admin` ، `ADMIN_EMAIL=...` ، `ADMIN_PASSWORD=...` ، `ADMIN_NAME=...`
در تب «محصولات»: قیمت را مستقیم عوض کن (با خروج از کادر ذخیره می‌شود)، موجودی را با ＋ و − کم و زیاد کن، محصول جدید بساز یا حذف کن.

### ساخت حساب مدیر (روش قدیمی)
یکی از دو راه:
1. در `.env` مقدار `ADMIN_MOBILE=09123456789` را بگذارید، سرور را بالا بیاورید و **با همان شماره در سایت ثبت‌نام کنید** → خودکار مدیر می‌شوید.
2. اول عادی ثبت‌نام کنید، بعد در سرور بزنید: `npm run make-admin 09123456789`

بعد از ورود، توی «حساب من» دکمه‌ی **⚙️ پنل مدیریت فروشگاه** نشان داده می‌شود.

## چه چیزهایی کار می‌کند؟

| بخش | توضیح |
|---|---|
| ثبت‌نام / ورود | رمز با scrypt هش می‌شود، نشست با کوکی `HttpOnly` (۳۰ روزه)، محدودیت تعداد تلاش ورود |
| محصولات | از دیتابیس خوانده می‌شود؛ مدیر می‌تواند اسم، قیمت، تخفیف، موجودی، عکس (لینک یا آپلود) را عوض کند، محصول اضافه/مخفی/حذف کند |
| سفارش | قیمت‌ها و تخفیف و هزینه‌ی ارسال **سمت سرور** حساب می‌شود (از کلاینت قبول نمی‌شود)، موجودی کم می‌شود، لغو سفارش موجودی را برمی‌گرداند |
| وضعیت سفارش | ثبت شده ← در حال آماده‌سازی ← ارسال شده ← تحویل شده (مدیر عوض می‌کند، کاربر در پنلش می‌بیند) |
| پنل شخصی | پروفایل، سفارش‌ها، علاقه‌مندی‌ها، آدرس‌ها، حیوان‌های من، تغییر رمز؛ همه روی سرور ذخیره می‌شود |
| کوچولوی برتر | آپلود عکس و امتیازدهی (برای ارسال و رأی باید وارد شد) |
| چندفروشگاهی | هر فروشگاه (شعبه) محصول، موجودی، سفارش و هزینه‌ی ارسال جدا دارد؛ مشتری در اولین ورود فروشگاه را انتخاب می‌کند (با یک فروشگاه فعال، خودکار) |
| نقش‌ها | `user` (مشتری)، `manager` (مدیر فروشگاه؛ فقط فروشگاه‌های خودش)، `admin` (مدیر کل: همه‌چیز + فروشگاه‌ها + تنظیمات سایت + نقش کاربران) |
| تنظیمات سایت | نام، شعار، تلفن، ایمیل، آدرس، بنر اعلان و «حالت تعمیر» (سفارش بسته می‌شود) از پنل عوض می‌شود |
| پنل مدیریت | تب‌ها: داشبورد، محصولات، سفارش‌ها، کاربران و نقش‌ها، فروشگاه‌ها، تنظیمات سایت (دو تب آخر فقط مدیر کل) |
| PWA و تنظیمات کاربر | قابل نصب روی موبایل؛ صفحه‌ی تنظیمات: تم (روشن/تیره/خودکار)، اندازه‌ی فونت، صدا، حالت آرام |

اگر `public/index.html` را بدون سرور (مثلاً دوبل‌کلیک روی فایل) باز کنید، سایت مثل قبل در «حالت محلی» با localStorage کار می‌کند؛ ولی وقتی از طریق سرور باز شود، خودکار به بک‌اند وصل می‌شود.

## ساختار پوشه‌ها

```
server.js               ← سرور و همه‌ی API ها
lib/db.js               ← دیتابیس فایلی (data/db.json) با ذخیره‌ی امن + بکاپ روزانه
lib/util.js             ← هش رمز، اعتبارسنجی، محدودیت درخواست
lib/seed-products.json  ← محصولات اولیه (اولین اجرا وارد دیتابیس می‌شوند)
public/index.html       ← سایت مشتری (اسکریپت‌های کلاسیک، بدون bundler)
public/css/app.css      ← استایل اصلی؛ extra.css ← استایل بخش‌های جدید
public/js/*.js          ← ترتیب بارگذاری در index.html مهم است (data, core, home, …, server-mode, ui)
public/admin.html + css/admin.css + js/admin.js  ← پنل مدیریت (سه فایل)
public/manifest.webmanifest, sw.js, icons/       ← PWA
public/assets/          ← عکس و صدای سایت
scripts/                ← make-admin، smoke-test (سرور)، e2e-site.py / e2e-admin.py / e2e-manager.py (مرورگر)
data/                   ← (خودکار ساخته می‌شود) db.json ، uploads/ ، backups/
PROGRESS.md             ← وضعیت پروژه و راهنمای ادامه‌ی کار در چت جدید
CHANGELOG.md            ← تاریخچه‌ی تغییرات
```

> نکته: چون اسکریپت‌ها کلاسیک‌اند، تابعی که در فایل بعدی تعریف می‌شود نباید هنگام لود فایل قبلی صدا زده شود.

## فروشگاه اصلی و رنگ‌های سایت (تب «تنظیمات سایت»)
- **فروشگاه اصلی:** همه‌ی مشتری‌ها فقط همین فروشگاه را می‌بینند؛ دکمه‌ی «تغییر فروشگاه» و صفحه‌ی انتخاب فروشگاه برای مشتری نیست و سرور هم پارامتر `?store` و `store` سفارش را از مشتری قبول نمی‌کند. فقط **مدیر کل** می‌تواند فروشگاه اصلی را عوض کند یا خودش فروشگاه دیگری را ببیند.
- **رنگ‌ها:** ۷ رنگ (اصلی، سبز ملایم، کرم، تأکید، پس‌زمینه، کارت، نوشته) با پیش‌نمایش و ۳ پالت آماده. روی تم روشن اعمال می‌شود (تم تاریک رنگ‌های خودش را دارد). رنگ نوشته‌ی روی دکمه‌ها خودکار سفید یا تیره می‌شود.

## مدیریت فروشگاه‌ها و نقش‌ها
- مدیر کل از تب «فروشگاه‌ها» فروشگاه می‌سازد/غیرفعال می‌کند (فروشگاهِ دارای سفارش حذف نمی‌شود، فقط غیرفعال می‌شود).
- از تب «کاربران و نقش‌ها» نقش کاربر را `manager` کنید و فروشگاه‌هایش را تیک بزنید. مدیر فروشگاه فقط محصول و سفارش همان فروشگاه‌ها را می‌بیند.
- مدیر کل نمی‌تواند نقش خودش را پایین بیاورد.

## تنظیمات فروشگاه
در ابتدای `server.js` بخش `CONFIG`: مقدار پیش‌فرض ارسال رایگان/هزینه‌ی ارسال (برای هر فروشگاه از تب «فروشگاه‌ها» جدا قابل تنظیم است) و کدهای تخفیف (`PET10` ده درصد، `WELCOME` برای اولین سفارش). بعد از تغییر، سرور را دوباره اجرا کنید.

## گذاشتن عکس واقعی محصولات
پنل مدیریت ← محصولات ← ویرایش ← «عکس»: یا لینک بدهید، یا فایل را آپلود کنید (خودکار کوچک می‌شود و در `data/uploads` ذخیره می‌شود).

## بکاپ
کل اطلاعات فقط داخل پوشه‌ی `data/` است. از همین پوشه کپی بگیرید. سرور هم هر روز یک نسخه در `data/backups` نگه می‌دارد (۱۴ روز آخر).

## گذاشتن روی سرور (VPS)
```bash
# با pm2
npm i -g pm2 && pm2 start server.js --name petherapy && pm2 save
# یا با Docker
docker build -t petherapy . && docker run -d -p 3000:3000 -v $PWD/data:/data -e ADMIN_MOBILE=09123456789 petherapy
```
پشت **nginx یا Cloudflare با HTTPS** بگذارید و در `.env` مقدار `COOKIE_SECURE=1` را بزنید. (ورود و رمز عبور بدون HTTPS امن نیست.)

نمونه‌ی nginx:
```
location / { proxy_pass http://127.0.0.1:3000; proxy_set_header X-Forwarded-Proto $scheme; proxy_set_header X-Forwarded-For $remote_addr; client_max_body_size 3m; }
```

## تست خودکار
- `npm test` → سرور موقت بالا می‌آورد و ۵۰ تست API (ثبت‌نام، سفارش، موجودی، نقش‌ها و دسترسی فروشگاه‌ها، تنظیمات سایت، حالت تعمیر، …) اجرا می‌کند.
- تست مرورگر (موبایل) با Playwright پایتون: `pip install playwright && playwright install chromium` سپس  
  `python3 scripts/e2e-site.py` (سایت: فروشگاه، سبد، ثبت سفارش، تنظیمات، انتخاب فروشگاه، PWA) و  
  `python3 scripts/e2e-admin.py` (پنل مدیریت با نقش مدیر کل: همه‌ی تب‌ها، ذخیره‌ی محصول/تنظیمات/فروشگاه) و  
  `python3 scripts/e2e-manager.py` (پنل با نقش مدیر فروشگاه: فقط فروشگاه خودش، ممنوعیت‌های دسترسی، مدیر با دو فروشگاه).  
  همه را با `npm run test:e2e` اجرا کنید.

## چیزهایی که هنوز نیست (صادقانه)
- **درگاه پرداخت آنلاین**: وصل نشده؛ فعلاً فقط «پرداخت در محل». بعداً کافی است در `POST /api/orders` ایجاد تراکنش و در یک مسیر callback تأیید پرداخت اضافه شود، و `CONFIG.online=true` شود.
- **فراموشی رمز با پیامک**: نیاز به سرویس پیامک دارد؛ فعلاً مدیر می‌تواند از پنل برای کاربر رمز جدید بگذارد.
- **دیتابیس فایلی** برای چند هزار سفارش عالی است؛ اگر فروش خیلی زیاد شد، بهتر است به PostgreSQL/SQLite منتقل شود (همه‌ی دسترسی‌ها فقط در `server.js` است).
- **عکس محصولات پیش‌فرض** از جستجوی Bing لود می‌شود (کار آماده‌ی خودتان)؛ برای پایداری، عکس‌ها را از پنل آپلود کنید.
